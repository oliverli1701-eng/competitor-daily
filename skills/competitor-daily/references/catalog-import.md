# 导入学院竞赛清单

输入可以是 PDF、DOCX、XLSX、CSV、JSON、Markdown 或纯文本；以当前 `import-catalog --help` 显示的支持类型为准。旧版二进制 `.doc` / `.xls` 或图片扫描件先用 Agent 可用的文档/OCR工具转换为文本或结构化文件，再导入。不要把无文字 PDF 的空结果误报为成功。

1. 在用户自己的 workspace 初始化品牌信息，导入原始文件。
2. 核对提取出的草稿与原文件，重点看跨页表格、合并单元格、同名赛事的不同赛道、等级列和备注列。
3. 列出需要用户判断的真实歧义。对于相同赛事的重复原始条目，保留原编号和等级来历；不要为了减少条数抹平等级冲突。
4. Agent 对照原件核对无误后运行 `confirm-catalog`，无需额外逐条询问用户；仅实质歧义或缺失需要用户澄清。不确定的草稿不直接进入付费批量检索。

`config/profile.json` 决定大学、学院与视觉品牌。目录清单和赛事来源分别维护，因此换学院不需要改 Python、HTML 或 PDF 模板。具体字段以初始化生成的配置为准。日后调整名单，应重新走草稿核对和确认流程，并保留历史报告本来的名称与日期。

对于 OCR 结果或复杂表格，可以由 Agent 对照原件整理以下 JSON，再导入。`id` 为唯一正整数，名称和等级应保留原件写法；不猜测官网链接。

```json
{
  "records": [
    {
      "id": 1,
      "name": "原件上的赛事名称",
      "suggested_level": "学院 A 类",
      "source_location": "第 2 页，第 3 行"
    }
  ]
}
```

可选 `official_urls` 是完整 HTTP(S) 官方网址的数组。`review`、核对摘要等由程序生成；不要伪造确认状态来跳过校验。

不要从旧安装中复制作者的 `.env`、个人清单、源文档或私有运行状态。发行样例只是演示输入，不是新用户的默认认可名单。
