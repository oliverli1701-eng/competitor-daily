# 架构与扩展

Competitor Daily 将可复用程序与用户工作目录分开。Skill 描述 Agent 的操作流程；Python 负责导入、校验、状态比较和稳定输出。不同平台共用程序，不需要把用户绑定到作者的服务器。

```text
用户文档 → 导入草稿 → 确认认可清单
                           ↓
官方页面与附件 → 有依据的赛事事实 → 历史比较
                           ↓
                  HTML / PDF / 结构化结果
                           ↑
               用户 profile 品牌配置
```

## 两种研究入口

直接 API 模式从工作目录 `.env` 读取用户自己的凭证；Agent 模式使用用户现有的检索工具，将研究批次交给 `run --from-research`。两者进入同一事件校验与渲染流程。模型提供方的输出仍需通过原文事实校验，不能绕过这一层直接变成公开日报。

## 开发入口

| 关注点 | 主要位置 | 扩展时保留的约束 |
| --- | --- | --- |
| 工作区与导入 | CLI 与 workspace 导入模块 | 原始名单与确认后的目录分开，不静默改成示例名单 |
| 来源与检索 | `contest_daily/network.py`、`scanner.py` | 官方来源范围、证据追溯、重试和缓存 |
| 事件结构 | `contest_daily/core.py` | 赛事编号、届次、赛道和日期不能混并 |
| 历史变化 | `contest_daily/state.py` | 无新证据不推断取消或截止；单赛事冲突隔离 |
| 视觉输出 | `product_ui.py`、`ui_styles.py`、`pdf_export.py` | 同一品牌配置与报告数据驱动 HTML/PDF |
| Agent 工作流 | `skills/competitor-daily/` | 独立用户目录、用户自有凭证、按需调度 |

以当前版本 `--help`、初始化配置与代码中的校验函数为准。增加输入格式时，输出已有的草稿结构；增加检索提供方时，输出已有的事实结构。新增赛事字段需同步验证、网页、PDF 与样例，而不是只在卡片中增加文案。

## 工作区与发布

安装路径保存运行程序、Skill 与模板。用户工作区保存 `config/profile.json`、认可清单、`.env`、研究缓存、状态和日报。升级安装程序不应覆盖工作区。

本地使用不需要服务器。自动更新、GitHub 归档和网站发布属于可选扩展，应先验证手动运行。推送失败单独重试，不再次付费检索；发布失败保留最后成功版本。令牌、日志、私有原始文件和研究证据默认不进入公共网站或仓库。
